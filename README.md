# 空间守护 SpaceKeeper

中文、离线的 Windows 重复文件清理助手。先看清占用和重复依据，再决定保留哪份、副本是否移入回收站。

**状态：0.1.0 桌面原型。支持 Windows 11 x64、本地 NTFS 固定磁盘。无需管理员权限，无账号、广告、云端或 AI 服务。**

## 下载和使用

解压便携包，保持所有 DLL 与 `SpaceKeeper.exe` 在同一文件夹，双击 `SpaceKeeper.exe`。便携包包含 .NET 运行时，不需要另装开发 SDK。

1. 点击「选择目录」，选择下载、桌面、文档、照片等个人文件目录。启动时不预选扫描目录。
2. 添加「受保护目录」。这些目录可以参与扫描，但里面的文件不能勾选回收。
3. 点击「开始扫描」。空间概览展示已支持文件的目录大小、大文件；目录大小包含子目录，不能相加。
4. 打开「重复文件」。每组文件经过大小筛选、SHA-256 和逐字节比较。默认保留一份，其他副本默认不勾选。
5. 指定需要保留的副本，手动勾选要回收的副本，点击「查看清理预览」。仔细比较原路径与保留路径，确认没有把有意保存的备份当成多余副本。
6. 点击「确认移入回收站」。程序重新检查身份、大小、修改日期和内容；变化或无法处理的文件跳过。处理后必须重新扫描才能继续清理。
7. 在「操作记录」查看结果，点击「打开回收站恢复」，在 Windows 回收站中选择文件并还原。

**移入同盘回收站通常不会马上腾出空间。** 程序分别报告回收文件的逻辑大小与各磁盘可用空间的实测变化；空间变化也可能来自其他程序。程序不提供永久删除或自动清空回收站。清空回收站是用户在 Windows 中自行决定的操作，清空后本工具不能恢复文件。

## 安全范围与限制

- 只接收用户主动选择的本地 NTFS 目录，不支持整盘根目录、网络盘或可移动盘。
- 排除 Windows、Program Files、ProgramData、AppData、回收站、OneDrive 及 Windows Cloud Files 注册的云同步目录；排除链接、系统标记、云占位、硬链接、多数据流、压缩和稀疏文件及常见软件依赖目录。
- 非 Cloud Files 注册的第三方同步/备份软件可能无法自动识别。不要选择这类软件管理的目录；内容相同也可能是有意保留的备份。
- 仅识别字节完全相同的文件；不判断文件是否「无用」，不合并不同版本，不清理软件缓存或相似照片。
- 图片支持缩略图，其他文件可打开所在目录。没有文档内容编辑器或相似度推断。
- 大文件和目录统计是已支持文件的逻辑大小，不是全盘占用或可保证释放的物理空间。被跳过的文件不计入统计；空文件不进入重复清理组。
- 最终回收由 Windows Shell 执行。回收前回调拒绝永久删除分支，并重新验证；不支持回收或发生异常时不调用永久删除后备。
- 处理期间锁住保留副本，阻止普通写入及删除；锁住待回收副本的写入。Windows Shell 仍按路径处理，无法承诺抵御其他程序在最后瞬间并发改名/替换路径；清理时应关闭会移动这些文件的软件。
- 操作前落盘「准备回收」，操作后记录结果。崩溃可能留下准备记录，此时请检查原文件和回收站，不要把准备记录当成已完成。
- 回收站容量、清理策略和用户后续清空会影响恢复。程序不承诺永久可恢复，不替代独立备份。

## 本机数据

受保护目录设置、操作记录保存在 `%LOCALAPPDATA%\SpaceKeeper`。扫描列表仅保存在内存；启动时不自动扫描。记录包含本机路径，请勿上传含个人路径的记录。应用没有网络请求或遥测代码。

## 从源码构建

安装 .NET 10 SDK，在 Windows 中执行：

```powershell
./build.ps1
```

产物位于 `dist/SpaceKeeper-win-x64`。脚本编译、运行安全检查、发布带运行时的便携程序。核心逻辑、WPF 界面和检查程序分别位于 `SpaceKeeper.Core`、`SpaceKeeper.App`、`SpaceKeeper.Tests`。安全检查不依赖第三方测试包。

```powershell
# 常规检查，只处理临时生成的测试文件
dotnet run --project SpaceKeeper.Tests

# Windows 桌面会话：真实回收并恢复一份专用测试副本
dotnet run --project SpaceKeeper.Tests -- --recycle-integration
```

真实回收检查只操作本次生成的 `.scratch/<随机编号>` 中的文件。不会扫描或清理个人目录，不会清空回收站。检查记录与已知限制见 [TESTING.md](TESTING.md)。

## 开源和手动上传 GitHub

创建新的公开仓库 `space-keeper`，解压源码 ZIP，上传项目目录里的全部内容，保留 `.github/workflows/check.yml` 和三个项目子目录。源码包不含 SDK、构建缓存和个人记录。便携包作为 GitHub Release 附件上传，不能把这个桌面程序作为 GitHub Pages 网页运行。

许可证为 MIT。附带 .NET 运行时保留其原有许可证和第三方声明；项目未复制 Czkawka 或 dupeGuru 的实现。

## 需求证据和用户验证

- 用户担心误删，更愿意保留重复文件：[Windows 重复图片求助](https://www.reddit.com/r/DataHoarder/comments/11u1xyd/software_for_finding_duplicate_images/)。
- dupeGuru 已提供参考文件保护与回收站处理：[官方结果说明](https://github.com/arsenetar/dupeguru/blob/master/help/en/results.rst)。
- Czkawka 已覆盖重复文件检测：[官方项目](https://github.com/qarmin/czkawka)。安全预览与保留副本属于基础要求，不是独创功能。

需求规模和实际留存尚未验证。请使用 [USER-VALIDATION.md](USER-VALIDATION.md) 招募五位用户测试；不要把自动检查通过写成用户验证完成。
